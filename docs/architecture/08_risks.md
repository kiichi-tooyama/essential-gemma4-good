# リスクと対策

## 主要リスク一覧

| リスク | 内容 | 対策 |
|---|---|---|
| iOS メモリ制約 | 大型モデル実行時に強制終了リスクが高い | 対応モデル制限、軽量 variant 提示、mmap、推奨 RAM 表示 |
| Android 端末差 | SoC / GPU 差異で品質が不安定 | 互換性プロファイル、CPU fallback、段階展開 |
| 発熱と電池消費 | 長時間推論で UX が悪化 | 連続推論制限、低電力モード、軽量モデル提案 |
| ストレージ不足 | モデル導入に失敗しやすい | 事前容量見積、LRU 削除、モデルサイズ可視化 |
| Adapter 互換性 | 量子化差異や base model 差異で attach 失敗 | compatibility matrix、署名済み manifest |
| IPC の差異 | Android / iOS で実装方式が揃わない | SDK 抽象化、共通プロトコル、OS 別実装分離 |
| 既存サーバー影響 | 他アプリ稼働環境へ負荷や構成影響が出る | パス、DB、ログ、artifact 配信を分離 |
| 審査 / 配布ポリシー | App Store / ストアポリシーと衝突する可能性 | モデルをデータとして管理し、審査説明を準備 |

## 優先度の高い設計原則

- 安定性を性能より優先する
- 推論失敗時は沈黙せず代替案を返す
- モデル配信と推論は責務を分離する
- OS 差異は無理に共通化しない

## 監視対象

- モデルダウンロード失敗率
- 署名検証失敗率
- 端末別 OOM 発生率
- adapter attach 失敗率
- 推論キャンセル率

## リリース前に確認すべき点

- 低 RAM 端末での最低成立ライン
- バックグラウンド復帰時の状態整合
- 部分ダウンロード破損時の回復
- 既存サーバー帯域影響
